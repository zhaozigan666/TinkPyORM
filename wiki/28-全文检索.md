# 28-全文检索

> [TinkPyORM](https://github.com/zhaozigan666/TinkPyORM) 技术文档 · [文档索引](Home.md) · 上一页： [27-JSON自动建表](27-JSON自动建表.md)

基于 SQLite **FTS5** 的全文检索（v0.10.0）。入口 `Db.fts(name)`，返回 `FtsIndex`。

## 两种模式

| 模式 | 存储 | 同步方式 | 适用 |
|---|---|---|---|
| `external`（默认） | 只存索引，原文留在主表 | `create()` 自动挂 INSERT / UPDATE / DELETE 三个触发器 | 与业务表配套，能取原文做高亮 |
| `standalone` | 索引与原文同处虚拟表 | 自己写 `INSERT INTO xxx_fts` | 没有主表、或不想让触发器介入 |

```python
# 外部内容模式：列从 docs 表结构自动推断（排除主键）
docs = Db.fts("docs")
docs.create()                            # 幂等：虚拟表 + 三个触发器

# 显式指定列与权重（bm25 权重按列顺序生效）
docs = Db.fts("docs", {"title": 5.0, "body": 1.0})
docs.create(prefix=(2, 3))               # 可选前缀索引

# 独立模式：必须给列
notes = Db.fts("notes", ["title", "body"], standalone=True)
notes.create()
```

实际虚拟表名为 `<name>_fts`；`Db.set_config({"prefix": "app_"})` 时表名同样带前缀。

## 建索引与维护

| 方法 | 作用 |
|---|---|
| `create(rebuild=False)` | 建虚拟表（外模式同时建触发器），幂等 |
| `drop()` | 删表与触发器，幂等 |
| `rebuild()` | 按内容表整体重建索引（批量导入后必做） |
| `optimize()` | 合并索引段、减小体积 |
| `integrity_check()` | 校验索引与主表一致性，失败抛 `QueryError` |
| `info()` | `{table, fts_table, mode, columns, tokenize, prefix, exists, rows}` |

`create()` 会先检查 SQLite 是否编译了 FTS5（`pragma_module_list`），没有则直接抛
`UnsupportedOperation`，不会执行到一半失败。

## 检索

```python
docs.search("SQLite OR 红烧肉").select()
docs.search('"全文检索"').select()          # 短语
docs.search("title:红烧肉").select()        # 列过滤
docs.search("红烧肉*").select()             # 前缀
docs.search("NEAR(SQLite 全文检, 10)").select()
docs.search(fts_quote("C++ 入门")).select() # 把任意文本变成安全的短语查询
```

检索串**始终以绑定参数传入 SQL**（`WHERE "docs_fts" MATCH ?`），因此不构成注入面；
非法 FTS 语法会被包装成 `QueryError`，原始消息保留在异常文本中。

### 链式方法

| 方法 | 说明 |
|---|---|
| `rank(reverse=False)` | 按 bm25 相关度排序（越小越相关） |
| `order(field, direction)` | 按字段排序，覆盖相关度排序 |
| `limit(n[, offset])` / `page(p, n)` | 分页 |
| `where(*args, **kwargs)` | 叠加内容表条件（仅外模式，多条为 AND） |
| `highlight(col[, open, close])` | 输出 `_highlight`（默认 `<em>` / `</em>`） |
| `snippet(col[, open, close, ellipsis, tokens])` | 输出 `_snippet` 摘要 |
| `cache(秒)` | 检索结果缓存，写主表时自动失效 |
| `select()` / `first()` / `count()` / `to_sql()` | 终端方法 |

结果行 = **主键 + 索引列 + `_score`**（+ 可选的 `_highlight` / `_snippet`）：

```python
rows = docs.search("全文检索").highlight("body").limit(5).select()
rows[0]["id"], rows[0]["title"], rows[0]["_score"], rows[0]["_highlight"]
```

`where()` 会编译成 `rowid IN (SELECT ... FROM 主表 WHERE ...)` 子查询，因此可以
在检索基础上继续用主表的普通字段过滤：

```python
docs.search("SQLite OR 红烧肉").where("category", "tech").select()
docs.search("SQLite OR 红烧肉").where({"category": "life"}).select()
```

## 分词器与中文

默认 `trigram`，中英文兼顾：

| 分词器 | 英文 | 中文 | 说明 |
|---|---|---|---|
| `trigram`（默认） | 好 | 好（≥3 字的子串） | 索引约为原文 3–5 倍 |
| `unicode61` | 好 | 差：整段中文是一个词元，搜「检索」找不到「全文检索」 | 索引小 |

**trigram 的硬下限**：查询词项少于 3 个字符必然 0 命中（子串滑窗长度为 3）。
这条已固化为测试契约（`test_two_char_trigram_returns_zero`），业务侧如需 2 字搜索，
请改用 `LIKE` 或换 `unicode61` + 外部分词。

```python
docs = Db.fts("docs", tokenize="unicode61 remove_diacritics 2")
docs = Db.fts("docs", tokenize="trigram")
```

## 与模型集成

```python
class Doc(Model):
    __table__ = "docs"
    __fts__ = {"columns": {"title": 5.0, "body": 1.0}, "tokenize": "trigram"}

Doc.fts_index().create()                 # 建索引（幂等）
rows = Doc.search("全文检索").rank().limit(10).select()   # Collection[Doc]
rows[0].title, rows[0]._score
```

未声明 `__fts__` 的模型调用 `search()` 会抛 `QueryError`，避免静默返回空集合。

## 写入与同步

外模式下主表的一切写入（`insert` / `insert_all` / `update` / `delete`、模型
`save()`）都由触发器同步，**不需要手动维护索引**：

```python
Db.table("docs").insert({"title": "向量检索入门", "body": "..."})
docs.search("向量检索").count()          # 1

Db.table("docs").where("id", 3).update({"title": "清蒸鱼教程"})
docs.search("红烧肉").count()            # 0
```

注意两点：

1. **批量导入**：`insert_all` 会逐行触发索引写入，十万级导入建议先灌数据、
   再 `docs.rebuild()` 一次性建索引；
2. **事务**：触发器与主表在同一事务内，回滚时索引一并回滚（已测试）。

## 缓存联动

FTS 表由触发器直接写入、不经过 `Query`，因此写主表时不会自动失效"检索结果缓存"。
本模块维护「内容表 → FTS 表」依赖注册表，`Query._invalidate_cache()` 会顺带清理：

```python
docs.search("红烧肉").cache(60).select()
Db.table("docs").where("id", 3).update({"title": "清蒸鱼教程"})
docs.search("红烧肉").cache(60).count()   # 0（缓存已失效）
```

## 边界与已知限制

1. **仅 SQLite**：`Driver.supports_fts` 为 `False` 的驱动在构造期抛 `UnsupportedOperation`；SQLite 未编译 FTS5 时在 `create()` 报错。
2. **trigram 3 字下限**：见上。
3. **索引体积**：trigram 约为原文 3–5 倍，`info()` 可查行数，体积需用 `dbstat` 或文件大小观察。
4. **`rank()` 必须基于检索**：`FtsQuery` 始终带 MATCH，故安全；不要把它拆成普通 `Query` 再按 `rank` 排序（普通查询没有 `rank` 列）。
5. **`where()` 仅外模式**：独立模式没有内容表，调用会抛 `QueryError`。
6. **列权重顺序**：`bm25()` 的权重按 `columns` 的声明顺序传入，改顺序等于改权重。

## API 速览

```python
# 索引
Db.fts(name, columns=None, *, tokenize="trigram", prefix=None,
       standalone=False, content_rowid=None, model=None)

idx.create(rebuild=False) / idx.drop() / idx.rebuild()
idx.optimize() / idx.integrity_check() / idx.info() / idx.search(query)

# 检索
q.rank(reverse=False) / q.order(field, direction) / q.limit(n[, offset]) / q.page(p, n)
q.where(*args, **kwargs) / q.highlight(col, open, close) / q.snippet(...)
q.cache(秒) / q.select() / q.first() / q.count() / q.to_sql()

# 工具
fts_quote(text)        # 任意文本 -> FTS5 短语查询
```
