# 注意事项与已知限制

> [TinkPyORM](https://github.com/zhaozigan666/TinkPyORM) 技术文档 · [文档索引](Home.md) · 上一页： [23-与think-orm对照表](23-与think-orm对照表.md) · 下一页： [25-开发与测试](25-开发与测试.md)


1. **内置驱动仅 SQLite**。驱动抽象层（`tinkpyorm.drivers`）已就位：新增数据库只需实现一个驱动类并用 `@register_driver("名字")` 注册，`Connection` / `Builder` / `Query` / `Model` 无需改动；MySQL / PostgreSQL 等驱动尚未提供。

   `type` 的合法性以**活注册表**为准（内置保留名 ∪ 已注册驱动名），因此注册后即可直接配置：

   ```python
   @register_driver("oracle")
   class OracleDriver(SQLDriver): ...

   Db.set_config({"type": "oracle", "database": "x"})   # 注册后立即合法
   available_type_names()                               # 当前可配置的类型名
   ```

   未注册的类型立即抛 `InvalidArgumentException`，错误信息会列出已注册清单并提示注册方式。注意 `mysql` / `postgresql` / `mssql` / `mongodb` / `redis` 属**预留名**：配置阶段放行，到建立连接时才因缺少驱动实现抛 `DriverNotAvailable`。
2. **`with_` 不是 `with`**：`with` 是 Python 保留关键字，预载入方法必须写成 `with_()`。
3. **`raw()` 不做转义**。它按字面量拼进 SQL，只应传入你自己硬编码的表达式，绝不可传入未校验的用户输入。
4. **`without_field` 有额外开销**：SQLite 不支持 `SELECT * EXCEPT(col)`，实现上先查 `PRAGMA table_info()` 推导出完整字段列表再剔除，多一次元数据查询。
5. **`cache()` 是进程内内存缓存**（v0.4.0 起为进程级共享 + TTL + LRU 上限），非跨进程持久缓存，进程重启即失效。链式查询的写操作会自动清除同库同表缓存，裸 SQL（`Db.execute`）需手动调用 `Db.clear_cache()`。
6. **`right_join()` 依赖 SQLite 版本**：`RIGHT JOIN` / `FULL JOIN` 需 **SQLite ≥ 3.39**（Python 3.11+ 通常自带 3.39+）。旧版本会报语法错误，此时请改写为 `LEFT JOIN` 或升级 SQLite。
7. **`withTrashed()` / `onlyTrashed()` 需先启用软删除**：若模型未配置 `__soft_delete__`，调用会抛 `QueryError`。
8. **`lock()` 在 SQLite 下无实际效果**（SQLite 是文件级锁，`FOR UPDATE` 不适用），保留方法仅为 API 对齐。
9. **获取器不改变存储值**：它只在读取时转换，查询条件里仍应使用数据库里的原始值。
10. **模型属性访问未加载字段返回 `None`**，而非抛 `AttributeError`，这是刻意为之（避免模板里频繁判空）。
11. **JSON 能力需 SQLite ≥ 3.38**（JSON1 内置版本；本项目在 3.53 上开发验证）。更早的版本需编译时启用 JSON1 扩展。JSON 路径查询如需高性能，请建表达式索引（详见 `PERFORMANCE.md` 第十一节）。
12. **JSON 复合值不支持相等比较**：`where_json(f, p, '=', [1,2])` 会抛 `QueryError`（JSON 文本比较受键序与空白影响，结果不可靠），请改用 `where_json_contains` 或 `where_raw`。
13. **未实现的 think-orm 特性**：虚拟模型、实体模型/分层、视图模型、数据自动验证器、分布式与断点重连。（MongoDB 支持已于 v0.12.0 落地，见 [30-MongoDB支持](30-MongoDB支持.md)。）
14. **全文检索依赖 FTS5**：SQLite 需编译 FTS5 模块（官方发行版默认包含），未编译时 `create()` 抛 `UnsupportedOperation`；非 SQLite 驱动（`Driver.supports_fts = False`）在 `Db.fts()` 构造期即拒绝。详见 [28-全文检索](28-全文检索.md)。
15. **trigram 分词有 3 字符下限**：查询词项少于 3 个字符必然 0 命中（搜「检索」找不到「全文检索」）。中文 2 字搜索请改用 `unicode61` + 外部分词，或在业务层用 `LIKE` 兜底；trigram 索引体积约为原文的 3–5 倍。
16. **MySQL 支持范围与验证边界**：覆盖 5.7.x / 8.0.x–8.4.x / 9.x，`version` 缺省按 5.7.0；越界（5.6、6.x、7.x、8.5）直接报错。v0.11.0 的 47 项 MySQL 测试是**离线**的（版本解析 + SQL 文本 + 门禁），未在真实服务器上跑集成测试，生产接入前请先用 `ping()` 与一条 `select` 自测。详见 [29-MySQL支持](29-MySQL支持.md)。
17. **MySQL 不支持文档集合与 FTS 索引**：`Db.collection()` / `Db.fts()` 在 MySQL 配置下构造期即抛 `UnsupportedOperation`（前者依赖 SQLite 专有能力，后者语义对应 `FULLTEXT + MATCH…AGAINST`，另作规划）。`Query.upsert()` 也仅 MySQL 可用。
18. **MongoDB 支持范围与验证边界**：覆盖 4.0.x / 4.2.x / 4.4.x / 5.0.x / 6.0.x / 7.0.x / 8.x，`version` 缺省按 4.0.0；越界（3.6、4.1、9.x）直接报错。版本门禁以**实际探测**的服务端版本为准（有权限时用 `buildInfo` 取精确版本，否则用 `hello` 的 `maxWireVersion` 取下界），显式声明的 `version` 退化为一条断言（声明高于实际服务端会在连接时报错）。v0.12.0 的 **118 项离线测试**覆盖过滤文档构造、输入校验、异常翻译、版本与拓扑矩阵；另附 **32 项真实服务端集成测试**（`test_mongo_live.py`，需环境变量 `TINKPYORM_MONGO_TEST_URI`，未设置则整份跳过），已在 MongoDB 8.3.13 单节点上以 5 万条数据实测通过。详见 [30-MongoDB支持](30-MongoDB支持.md)。
19. **MongoDB 不支持事务与 ORM 模型层**：MongoDB 多文档事务（4.0+，且需副本集）需显式 session，与本项目 `Db.transaction()` 的 SQL 语义不兼容，故 `supports_transactions = False`；`Model` / 关联 / JOIN 均为关系型概念，MongoDB 侧不可用，请用 `MongoCollection` + `schema()`。`Db.collection()` 始终是 SQLite 文档存储，MongoDB 侧请用 `Db.mongo()`。
20. **MongoDB 需显式 limit**：未指定 `limit()` 时本层套用默认上限 1000（`options["max_limit"]` 可调），避免一次查询拖垮内存；深翻页请用 `after()` 游标分页而非 `page()`（偏移量分页的 `skip` 代价随页码线性增长）。无索引的 `where` 会退化成 COLLSCAN，建索引前请用 `explain()` 自查。
21. **MongoDB 能力受部署拓扑限制**：多文档事务需要副本集或分片集群，**单节点部署即使版本够也不支持**（实测 8.3.13 standalone 上 `transactions` 为 False）。能力判定是「版本 + 拓扑」双门禁，拓扑未知时不拦截。受拓扑限制的能力见 `MONGO_TOPOLOGY_FEATURES`。
22. **Redis 支持范围与验证边界**：覆盖 4.0.x / 5.0.x / 6.0.x / 6.2.x / 7.0.x / 7.2.x / 7.4.x / 8.x，`version` 缺省按 7.0.0；越界（3.2、6.1、7.1、9.0）直接报错。Redis 的小版本是**发布线**而非补丁号，故按 `(major, minor)` 精确匹配，只对 8.x 放开所有小版本。版本门禁以 `INFO server` 的**实际探测值**为准，显式 `version` 退化为断言（`INFO` 被 ACL 拒绝时退化为声明值，不把权限问题误报成连接问题）。v0.13.0 的 **114 项离线测试** + **59 项真实服务端集成测试**（`test_redis_live.py`，需环境变量 `TINKPYORM_REDIS_TEST_URL`，未设置则整份跳过），已在 Redis 8.10.2 上实测通过。详见 [31-Redis支持](31-Redis支持.md)。
23. **Redis 的 `database` 是 db 序号**：0–15 的整数（由服务端 `databases` 决定），不是库名；非整数配置**直接报错**而不是静默当 0。集群模式只有 db 0，`SELECT` 不可用（`driver.supports_feature("select_db")` 返回 False）。
24. **Redis 不封装 Cluster 路由与模块能力**：驱动使用单节点连接（`redis.Redis`），连集群需自行传 `RedisCluster` 或前置代理；RedisJSON / RediSearch / Bloom / TimeSeries / Vector Set 属**模块**能力（服务端可能未加载），本层只登记 `vector_set` 的版本门槛，实际调用请走 `store.client()`。集群下多键命令要求同 slot，请用 `{tag}` 形式的键名。
25. **Redis 有两处硬护栏**：`keys()` 在 db 键数 > 10000 时**拒绝执行**（`KEYS` 是阻塞命令，请改用 `scan_iter`）；`clear()` 拒绝 `""` / `"*"` 模式（Redis 无"库"概念，整库删除会误伤同实例其它应用）。流水线只接受**已登记**的命令，未登记命令需 `pipe.raw()`（键名前缀自行处理）——猜错前缀会静默写错键，比报错危险。
