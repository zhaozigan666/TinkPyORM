### 文档布局

| 位置 | 职责 | 何时改 |
|---|---|---|
| `README.md` | 门面：简介、特性、安装、快速开始、文档导航、更新记录 | 新增特性 / 发版 |
| `wiki/*.md` | 按主题拆分的技术文档（用法与语义） | 增删 API、语义变化 |
| `docs/*.md` | 设计文档（架构决策、扩展映射、重构记录） | 架构级改动 |
| `PERFORMANCE.md` | 实测基准与优化记录 | 有新的实测数据 |

新增 API 时至少要同步 `wiki/22-API速查表.md` 与对应主题页，并在 README 的
「更新记录」追加条目。**`test_readme_examples.py` 是手写断言集**（不解析
Markdown），它校验的是**用法示例可运行**，因此 API 行为变化必须同时更新它。

**「更新记录」的写法（用户约定）**：**只记录"更新了什么"，不写原因**——不写根因
分析、设计动机、取舍论证、踩坑解释；按版本用短条目（`-` 列表）罗列，一条一个
变更事实，语句简洁明了。结构为「版本号 + 一句短主题（名词短语）+ 条目清单」，
可写的事实包括：新增 / 变更 / 移除的 API 与行为、配置项、测试项数、文档变动。
**设计动机与原理写在 `docs/` 或本 wiki 的主题页里，不塞进更新日志。**

## 发布到 GitHub Wiki

GitHub Wiki 是**独立的 git 仓库**（`<repo>.wiki.git`），与主仓库不共享文件树，
不能直接复制 `wiki/`：链接形态不同，且 `README.md` / `docs/` / `PERFORMANCE.md`
在 wiki 仓库里并不存在。统一由脚本做变换与校验：

```bash
# 生成 + 校验（--out 指向 wiki 仓库工作区，可放在主仓库之外）
python scripts/sync_wiki.py --out ../TinkPyORM.wiki
# 生成 + 提交 + 推送
python scripts/sync_wiki.py --out ../TinkPyORM.wiki --push
```

脚本做三件事：

1. **改写链接**：`NN-主题.md` → `NN-主题`（Gollum 页面 URL 无扩展名）、
   `Home.md` → `Home`、`../README.md` 等仓库内文件 → 绝对 URL。
   遇到未登记的新链接形态会**直接报错退出**，避免静默产生死链。
2. 生成 `_Sidebar.md`（分组与顺序自动跟随 `Home.md` 的表格）与 `_Footer.md`。
3. **校验零丢失**：页面齐全、内部链接可达、无残留 `../`、代码围栏数量一致、
   正文行多重集一致（仅链接目标允许变化）。

> 首次发布的前置条件：GitHub 只在**第一个页面经由网页创建后**才会建立 wiki
> 仓库，在此之前推送会报 `Repository not found`，且 REST API 没有 wiki 端点。
> 因此在仓库的 Wiki 页面点一次「Create the first page」后，脚本即可正常推送。
> 之后每次改完 `wiki/` 跑一次同步命令即可，`wiki/` 始终是唯一内容源。
